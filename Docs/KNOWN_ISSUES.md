# KNOWN ISSUES

## 1. 引擎与原规范不一致（决策项，非 Bug）

用户提供的执行手册指定 UE5 + C++。实测本机：

| 检查项 | 结果 |
|---|---|
| Epic Games / UE 安装 | 不存在 |
| C 盘剩余 | 16 GB（UE5 引擎 + 城市工程需 100 GB+） |
| GPU | RTX 5060 Laptop 16 GB — 足够 |
| Godot | 4.4.1 stable 可用，headless 可验证 |

**决策**：改用 Godot 4.4.1 实现可运行的 Vertical Slice。
理由：手册第三十四条要求"优先保证最终项目可以真正运行""不要伪装成已经完成"。
在此环境写 UE5 C++ 产出的是一堆无法编译、无法运行、无法验证的代码，
正好违反手册自身的验收标准。

**UE5 技术 → 本项目替代方案**

| UE5 | Godot 实现 |
|---|---|
| Nanite | 合并网格 + 程序化立面着色器（一个 chunk 一次 draw call 画出全部窗格） |
| Lumen | 天空 IBL + 屏幕空间反射 + 移动反射探针（SDFGI 在高质量档） |
| Virtual Shadow Maps | 4 级联 PSSM 方向光阴影 |
| World Partition | 250 m chunk 流式加载 + 碰撞分层加载 |
| TSR / DLSS | MSAA + FSR 不可用 → `scaling_3d/scale`（部分实现） |
| Niagara | GPUParticles3D |
| Mass AI | MultiMesh 人群 + 轻量代理状态机 |
| PCG Framework | GDScript 程序化格网（对偶图街区） |
| GAS | 不做（待实现） |
| Chaos Vehicles | VehicleBody3D + VehicleWheel3D 光线投射车辆物理 |

## 2. 未消除的性能缺口（P7 判"部分实现"的唯一原因）

单 chunk 构建 17.3 ms，仍是 7 ms 帧预算的 2.5 倍。因为一次构建不可拆分，
流式器每帧最多建一个 chunk，所以加载期实测 15-29 FPS，约 6 s 后回到 45-55 FPS。

| 阶段 | 实测 | 还能做什么 |
|---|---|---|
| blocks 8.3 ms | 12 种街区的真实几何生成，无冗余查询（`CellFacts` 已缓存） | 只能靠线程构建：`ChunkBuilder` 目前是 GDScript 静态函数且读写 `CityData` 的共享缓存，非线程安全 |
| ground 7.7 ms | 其中 water 5.4 ms 集中在沿江 chunk（内陆 chunk 约 1.9 ms） | 江面距离场预计算（膨胀集已有，缺精确值的粗-精两级化） |
| streets 0.9 / furniture 0.4 ms | 已按 ring 用 `detail` 开关裁剪 | — |

**已试过并回退的方案**：把远处 chunk 的地面网格从 25 m 放宽到 50 m，ground 从 8.0 降到 3.5 ms，
但相邻 chunk 的边顶点不再重合，高架底部出现可见裂缝与竖向穿帮 —— 共享顶点优先于省采样，已回退。

## 3. 量化副作用（可接受，但必须记账）

- 距离/强度/公园/区划四类查询走 25 m 量化备忘格，岸边判定可偏移至多 25 m。
  因此 `in_water` 刻意走**精确**路径（角色、桥梁/隧道判定、出生点都依赖它），
  批量生成才用量化版 `water_dist_q`。
- 行政区归属按 100 m 取整缓存，导致格心靠近区界时街区类型可能翻转：
  普查数字相对量化前为 plates 7317→7316、edges 10531→10529，cells 不变。
- 地面泥滩带（宽 14 m）按节点而非格心判定，岸线呈 25 m 阶梯；
  该带几乎完全在水面之下，暂不处理。

## 4b. 创造系统（Phase 19）已知的边界

- **只做了建筑工具**。道路/地形/装饰/车辆/NPC/任务六个工具位（按键 2-7）只弹"待实现"提示，
  不产生任何世界修改 —— 不做空壳按钮。
- **无 3D 拖拽 Gizmo**。移动用方向键（Ctrl+方向键 ×5 步长）、旋转 R、缩放 [ ]，
  全部走同一套撤销栈。规范里"类似 Unreal Editor 的轴向 Gizmo"未实现。
- **放置不做合法性校验**：可以把楼放进江里、别的楼里、马路上。
  规范 Phase 21.6 的"生成后验证"目前完全缺失。
- **作品不参与流式卸载**：`CreationSystem` 下的节点常驻场景树，
  走出 12 km 也不会回收；数量上去以后是内存问题，尚未测量。
- **存盘是全量覆盖**，无多存档、无版本迁移；`version` 字段已写但没人读。
- HUD 的"选中 #-1"在未选中时显示 -1，属显示瑕疵。

## 5. 待观察

- `Assets._env_mats` 只增不减，材质变体数量由道路宽度种类决定（当前 19 条主干道 × 少量档位，可控）
- 人行道采用齐平高差（y=0.02）而非真实 0.15 m 抬升：避免 CharacterBody3D 在路缘石处被卡住。视觉上靠路缘石几何 + 材质分界表现。
- 玩家在江面上可行走（无水面阻挡），需后续加水体触发区
- 苏州河与黄浦江交汇处（外白渡桥）的桥梁与路网冲突尚未消解
- 降水粒子开拖尾后帧率从 51 掉到 23（1280×720），雨天需要降拖尾或降粒子数档位
