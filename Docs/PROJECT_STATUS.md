## 本轮修掉的真实缺陷（全部由运行结果发现，非静态阅读）

Part 8（城市模拟）新增的六条，症状都是"看起来正常"：

| # | 症状 | 根因 |
|---|---|---|
| S0 | **模拟一整年，钱一分不差，商铺却从 12212 塌到 438** | 消费预算按 `人口 × 工资 × MPC` 授信，而工资只发给就业者；`SHOPS_MAX=400` 把就业上限锁死在劳动力 6%，房租汇进只进不出的房东桶。守恒检测对此完全无感——守恒是必要条件，不是充分条件。改为按余额支出 + 房东消费 + 超出储备的利润回流家庭，商铺上限由劳动力池推导 |
| S1 | 四类价格自播种值起**永远不变**，状态里看着像有定价 | 2 % 步长被 `int()` 截断：`int(32 × 1.02) = 32`。改 `roundi` |
| S2 | 所有类别恒判"空闲"，价格只会单边下调 | 上座率用 `小时人流 ÷ (数量 × 260 × 24)`，把小时流量除以日容量，量纲错误。改为 `营收折算件数 ÷ 小时吞吐` |
| S3 | 同一场雨：TrafficSystem 减车、CitySim 增需 | 天气被两套互不相容的模型各自解释。删除车辆数上的湿度项，湿度只影响车速 |
| S4 | 消费端接没接入，日志与截图都看不出来 | 未接入时 `crowd_factor` 返回默认 1.0，与接入后完全一致。加断言直接比较 `crowd.sim == sim`，并让系数在空区返回 1.0、有区返回真实值 |
| S5 | 性能门禁 `GATE-FAIL` 打印后流水线仍报 `PIPELINE: PASS` | `require()` 只 printf，不置失败位。改经 `die()`，并跑负测确认 `RUNFAIL=1` |
