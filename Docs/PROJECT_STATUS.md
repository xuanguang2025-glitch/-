## 本轮修掉的真实缺陷（全部由运行结果发现，非静态阅读）

Part 12（城市生命层）新增的六条。共同点：每一条都"看着能跑"，靠无头启动、断言或 HUD 才暴露：

| # | 症状 | 根因 |
|---|---|---|
| L0 | 无头启动报 144 条 `Could not find type "CitySim"/"CityLife"`，整个工程不编译 | 我让 CitySim 创建并持有 CityLife，而 CityLife 又要读 CitySim —— GDScript 在**解析期**解析全局类名，类环无法解出。改为账本只发 `ticked`，生命层订阅；装配收进 `LifeMount` 一行。同理 CityLife 不能持有 `CrowdSystem` 类型字段，只能按 group 取 |
| L1 | 同种子两座城市推进 120 小时后 `state_hash` 天差地别（1890150051 vs 56167315） | 人口随机源在 `CityLife._ready()` 播种，而测试里 detached 的 CitySim **不在场景树中，`_ready` 永不触发**，于是每个实例各自拿到平台默认种子。改到 `attach()` 里播种，并加"人口队列逐位一致"断言 |
| L2 | 商铺确实在开关店，新闻线跑 600 小时**一条商业新闻都没有** | 新闻线用 `events.size()` 判断"有没有新事件"，而事件表是 200 条环形缓冲 —— 装满之后长度恒为 200，新事件永远不可见。改为 CitySim 单调递增 `event_seq`（并入快照），并把它写进 `_event()` 的注释里 |
| L3 | 断言"行人和车辆把行程发布进了需求图"读到 0 格，"需求消散"读到 1 格不空 | 汇总量（峰值 / 格数 / 最堵路口）只在 `decay()` 里折叠；测试只写入不衰减时读到旧值。改为脏标记 + 读时折叠，且 `decay()` 自身必须置脏（否则清空后峰值仍报有人） |
| L4 | HUD 显示 `拥堵 8638.49`、`同时 179474 人次出行，车速降至 42%` —— 全城每条街都被钉在减速下限 | 占用量**按帧累加**而不是按秒：fps 越高城市越堵，且玩家站得越久越堵，稳态根本不存在。改为 `units × delta / RETENTION`，使场的稳态等于格内实际存在的加权主体数（人 1、车 8），容量常数才有物理含义 |
| L5 | 人口迁移一上线，所有居住区都在持续失血 | 把 CitySim 的 `employed`（只有店员）当成全区就业，于是 15 万人的街区"失业率 98%"、永远触发迁出。改为对**变化量**响应 —— 本地经济在招还是在关，才是人会反应的那件事 |

L4 与 L5 都不是断言逼出来的，是**看 HUD 截图和看日志**看出来的。所以本轮把拥堵、虚拟人口、消费笔数与新闻标题一并写进 HUD：读数本身就是门禁。

Part 8（城市模拟）新增的六条，症状都是"看起来正常"：

| # | 症状 | 根因 |

| S0 | **模拟一整年，钱一分不差，商铺却从 12212 塌到 438** | 消费预算按 `人口 × 工资 × MPC` 授信，而工资只发给就业者；`SHOPS_MAX=400` 把就业上限锁死在劳动力 6%，房租汇进只进不出的房东桶。守恒检测对此完全无感——守恒是必要条件，不是充分条件。改为按余额支出 + 房东消费 + 超出储备的利润回流家庭，商铺上限由劳动力池推导 |
